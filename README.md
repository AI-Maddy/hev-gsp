# HEV-GSP: a multilayer graph-signal dataset from a power-split hybrid vehicle model

This package simulates a mid-size, front-wheel-drive power-split hybrid electric vehicle (HEV). The physical model covers:

- vehicle dynamics;
- the planetary e-CVT, engine, MG1/MG2 and inverter;
- the Li-ion pack;
- the thermal networks;
- brakes, tires and the 7-DOF ride model;
- 12 V supply and HVAC.

The vehicle runs under a zonal E/E architecture:

- AUTOSAR Classic Platform endpoint ECUs on CAN FD;
- two Classic Platform zonal gateways;
- two AUTOSAR Adaptive Platform machines (central vehicle computer and telematics unit), modeled on the Adaptive Platform implementation CAPI v1.0.0.

Every sensor channel and every network element is exported as a node of a **multilayer graph** (64 nodes) with ground-truth structural edges. The data target four graph-signal-processing tasks:

- fault detection and localization;
- denoising;
- sparse-sensor reconstruction;
- topology inference.

## Getting the data

The code, graph files, figures and results live in this repository. The dataset itself (11 HDF5 parts, about 225 MB) is attached to the GitHub Release as assets, so it does not bloat the git history.

```bash
pip install -r requirements.txt
scripts/download_data.sh AI-Maddy/hev-gsp v1.0.0     # downloads dist/hev_gsp_*.h5 and verifies SHA256SUMS
```

To rebuild everything from scratch instead:

```bash
python generate_dataset.py --out data --workers 4   # about 11 min on 2 cores
python export_hdf5.py                                # writes dist/*.h5
python gsp_experiments.py && python make_figures.py
```

The ara::com code generated by CAPI is not committed, because AUTOSAR releases CAPI output for information only. Regenerate it with `scripts/generate_capi_code.sh /path/to/capi`.

## Graph

| Layer | Nodes | Signal per node |
|---|---|---|
| Physical (47) | Sensor channels: vehicle/IMU, 4 wheel speeds, 4 TPMS, 8 suspension, brakes, engine, MG1/MG2/inverter, battery, DC-DC, thermal loops, cabin/HVAC | Physical value (units in `nodes.csv`) |
| E/E (17) | 10 CP ECUs (ECM, PCU, ESC, EPS, DCDC_ECU, TMS, BMS, SCU, TPMS, CCU), 2 CP zonal gateways, CVC and TCU (Adaptive Platform), 2 CAN FD buses, 100BASE-T1 backbone | ECU: mean end-to-end latency (ms). Gateway: sojourn time (ms). CVC/TCU: latency (ms). Bus: utilization (%) |

The graph has 166 edges:

- **Physical layer (99 structural edges).** An edge $i$–$j$ exists when the governing equation of one quantity contains the other. Edges are typed kinematic, mechanical, control, electrical, or thermal.
- **E/E layer (20 edges).** CAN FD attachment, Ethernet links, and ara::com provider–consumer relations.
- **Interlayer (47 edges).** Each sensor links to the ECU that samples it.

`graph.npz` provides:

- the binary adjacency `A`;
- the signed correlation weights `W_signed` on the edges, and `W_abs`;
- the nominal normalization statistics `mu_nominal` and `sd_nominal`.

Use the signed Laplacian $L=D_{|W|}-W$. It is PSD and handles the negatively coupled pairs, for example MG1 speed versus engine speed.

## Scenarios and labels

**Nominal runs (30):**
- 5 drive cycles: urban, suburban, highway, hilly, and a WLTC-shaped "mixed" cycle;
- 3 ambient temperatures: −5, 20 and 35 °C;
- 2 seeds, which form the `train` and `test` splits.

**Fault runs (60):**
- 15 fault types × 2 severities × 2 operating conditions.
- Ambient temperature and cycle are rotated so that severity is not confounded with temperature.
- Each fault has its onset between 300 and 500 s.

| Layer | Faults |
|---|---|
| Physical (act inside the equations and propagate) | battery R0 growth, electric-drive pump flow loss, MG2 inter-turn short, misfire, thermostat stuck open, FL slow tire leak, RR damper oil loss, front brake drag, DC-DC degradation |
| Sensor | yaw-rate bias drift, battery-temperature sensor stuck, FR wheel-speed dropouts |
| E/E | ESC babbling idiot on CAN FD, DoIP (ISO 13400) flood on the front zonal gateway, BMS OS task overrun |

**Per-sample labels:**
- `fault_id` (0 = nominal; the IDs are in `faults.csv`);
- `fault_level`, the activation profile times severity.

**Per-run metadata:**
- primary node;
- component node set, for localization scoring;
- onset, severity, cycle, ambient.

Each run also stores `X_clean` (ground truth) and `X_meas`:

- Physical nodes: sensor noise plus quantization to the CAN signal resolution and range. SAE J1979 scaling applies where a PID exists.
- E/E nodes: measurement noise.

Auxiliary series include:

- engine on/off;
- battery power;
- actual engine torque;
- E2E error counts per ECU;
- PHM deadline failures;
- CPU loads.

## Loading

```python
import glob, h5py, json
runs = {}
for fn in sorted(glob.glob("hev_gsp_*_part*.h5")):
    f = h5py.File(fn)
    names = [n.decode() for n in f["graph/names"]]
    A, W = f["graph/A"][:], f["graph/W_signed"][:]
    for rid, r in f["runs"].items():
        runs[rid] = dict(X=r["X_clean"][:], Y=r["X_meas"][:], fault_id=r["fault_id"][:],
                         split=r.attrs["split"], faults=json.loads(r.attrs["faults_json"]))
```

In MATLAB: `h5read('hev_gsp_faults_part01of07.h5','/runs/<run id>/X_meas')`. The array comes back transposed, as 64×12000. `h5info` lists the run IDs in each part.

## Standards basis for the E/E layer

| Element | Basis |
|---|---|
| Signal → I-PDU → frame, transmission modes, filters | AUTOSAR CP SWS COM (`ComTxModeMode` PERIODIC/MIXED, `TRIGGERED_ON_CHANGE`, `MASKED_NEW_DIFFERS_MASKED_OLD`, `ComMinimumDelayTime`, `ComTimeout`) |
| CAN FD frame length and arbitration | ISO 11898-1:2015 (500 kbit/s / 2 Mbit/s) |
| E2E protection | AUTOSAR E2E Profiles 11 and 05, header layout as implemented in CAPI `isoft/e2e` |
| Signal resolution | CompuMethod linear scaling; SAE J1979 PIDs 0x0C (engine speed) and 0x05 (coolant temperature) |
| Adaptive communication | ara::com over SOME/IP (CAPI `nsomeip`): service/event IDs and eventgroups in `adaptive/hev_someip_deployments.arxml` |
| Health monitoring | CAPI `phm` DeadlineSupervision on the energy-management inputs |
| Diagnostics fault | DoIP (ISO 13400) / UDS (ISO 14229) request flood |

The DBC and ARXML files load in `cantools` (strict mode) and round-trip encode/decode. The Adaptive ARXMLs pass CAPI `aragen` validation and generate code:

```bash
aragen -g CODE -e /HEVApps/exe/energy_mgmt -o out isoft/arxmls <this>/adaptive
```

## Baseline results

These are baselines to benchmark against, not tuned "best" methods. All figures are in `figures/`, and all numbers are in `results/`. Hyperparameters are tuned on the training runs and evaluated on the held-out test and fault runs.

**Smoothness (Fig. 2).** On the physical layer, test signals (z-scored with training statistics) are markedly smooth on the structural graph with signed weights.

| Graph | Normalized total variation |
|---|---|
| Structural graph, signed weights | 0.056 |
| Degree-preserving random rewirings (50 draws) | 0.196 ± 0.030 (structural graph is 4.7σ lower) |
| Structural graph, binary | 0.135 |
| Full multilayer graph | 0.048 (random rewirings: 0.219 ± 0.037) |

The lowest 25 % of graph frequencies hold 77 % of the energy, against 28 % for the random rewirings.

**Denoising (Fig. 3).** NMSE in dB for additive white noise on the z-scored physical layer:

| SNR (dB) | −5 | 0 | 5 | 10 | 15 | 20 |
|---|---|---|---|---|---|---|
| no filtering | 5.0 | 0.0 | −5.0 | −10.0 | −15.0 | −20.0 |
| graph Tikhonov | −1.9 | −4.3 | −7.4 | −11.1 | −15.4 | −20.2 |
| PCA subspace | −2.3 | −5.0 | −8.3 | −12.3 | −16.8 | −21.4 |
| temporal Tikhonov | −7.8 | −9.5 | −11.1 | −13.4 | −16.2 | −20.4 |
| time-vertex Tikhonov | **−8.1** | **−9.7** | **−11.1** | **−13.5** | −16.4 | −20.5 |

Under the realistic sensor-noise model, the measured signals are already at −19.2 dB NMSE, and filtering gains at most 0.5 dB (time-vertex: −19.7 dB).

**Sparse-sensor reconstruction (Fig. 4).** NMSE on the unobserved nodes, from noisy observations:

| Method | 20 % of nodes | 50 % of nodes |
|---|---|---|
| graph Tikhonov (random sampling set) | −1.9 dB | −4.1 dB |
| LMMSE / kriging with the full training covariance | −4.3 dB | −7.5 dB |
| strict bandlimited LS | unstable (> 0 dB) | unstable (> 0 dB) |

LMMSE uses the full training covariance, so it carries more information than the graph. Strict bandlimited LS is unstable because the signals are low-pass but not bandlimited. A graph with learned weights, or a covariance-aware graph prior, is an obvious research direction here.

**Fault detection and localization (Figs. 5–6).** 60 fault runs; threshold at 1 % false-alarm rate on the nominal test runs; statistic = mean of the three largest per-node statistics over a 5 s window.

| Method | Mean AUC | Detected | Median delay | Top-1 localization | Top-3 localization |
|---|---|---|---|---|---|
| per-node z-score | 0.667 | 73 % | 105 s | 48 % | 60 % |
| PCA SPE | 0.751 | 75 % | 92 s | **67 %** | **77 %** |
| graph high-pass | 0.682 | 78 % | 91 s | 55 % | 73 % |
| graph neighbour regression | **0.764** | **82 %** | **49 s** | 60 % | **77 %** |

The graph neighbour regression predicts each node from its graph neighbours, with ridge regression fitted on nominal data. It is strongest on sensor faults that break a physical relation (yaw-rate bias 0.87; wheel-speed dropouts 0.95) and on E/E faults. Slow thermal and degradation faults (battery R0, MG2 winding, damper, stuck thermostat) remain hard for every baseline, because their signatures stay inside the nominal envelope for many minutes. Those are the open cases for a new method.

**Topology inference (Fig. 7).** Recovering the 99 structural physical edges from nominal data (AUPRC; chance = 0.09):

| Method | AUPRC |
|---|---|
| graphical lasso on shrunk covariance | **0.52** |
| partial correlation (Ledoit-Wolf) | 0.49 |
| smoothness-based learning (Kalofolias) | 0.38 |
| correlation | 0.35 |

Control and thermal edges are the hardest to recover.

## Limitations

- **Plant fidelity.** The plant is a control-oriented lumped-parameter model, not a validated replica of a production vehicle. Parameters are representative of published mid-size power-split HEVs.
- **Drive cycles.** The "mixed" cycle has the WLTC phase structure but is not the regulatory speed table.
- **E/E layer.** It is a stylized frame-level simulation: CAN FD arbitration and COM timing are simulated, but CRCs are not computed and ECU software is not executed. The Adaptive side is modeled with CAPI's ARXML format and code generator; CAPI binaries are not run.
- **Engine warm-up.** In EV-heavy low-speed driving the engine coolant warms slowly (as in real HEVs). Cold urban runs may not reach thermostat temperature within 20 min.
- **Signal rates.** Suspension signals are 0.1 s window features (mean travel, RMS acceleration), not raw 400 Hz data.
